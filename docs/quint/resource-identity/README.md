# Stable identities in the shipped resource reference

[fixed.qnt](fixed.qnt) is a maintained bounded replay contract for the shipped `ResourceProvider`. [adapter.py](adapter.py) drives the **actual imported** `create`, `delete` and `list` methods with Quint-generated events and compares real observations with every emitted `observed` state. It records returned resource names and object references; it does not implement an alternative Python allocator or resource model.

[audit.qnt](audit.qnt) remains the unchanged historical pre-fix model from source revision `389c5bb84f7ab186fa9c7815c2e15cb9332b67a4`. Its length-derived allocation witness intentionally replaces a live identity. The immutable historical file's SHA-256 is recorded in [manifest.json](manifest.json); maintained behavior belongs in `fixed.qnt`.

## Run model checks and actual API replay

From the repository root with the CI-pinned Node.js version available:

```sh
uv sync --locked --all-packages --no-default-groups --extra debt --extra django --extra celery
uv run --no-sync python scripts/quint/replay.py --topic resource-identity
```

The shared runner installs the pinned `scripts/quint/package-lock.json` toolchain when needed, requires Quint **0.33.1**, typechecks/checks the maintained model, emits fresh ITF scenario/sample traces and replays them through the implementation. CI executes model checks **and** replay with semantic mutation controls. Tooling/import/setup failures never count as detected regressions; missing or empty generated traces, unknown events, observation mismatches or surviving mutants fail the command. Old traces are cleared before generation.

The manifest fixes seed `20261107`, 150 sampled histories, 16 emitted sample traces of at most nine API transitions and four named witness traces. Artifacts in `.artifacts/quint/` retain ITF inputs, command logs, source head/hashes, production import attestation, mutation mismatches and run status; CI uploads them on failure too. Recheck a saved generated trace with:

```sh
uv run --no-sync python scripts/quint/replay.py --topic resource-identity --replay .artifacts/quint/resource-identity/sample-0.itf.json
```

The default command additionally requires all declared actions/witnesses and rejects semantic mutants using the same emitted traces. Minimal Django settings permit importing the real shipped module; **no database query, PostgreSQL server or production method patch is used in positive replay**.

## Source/action mapping

| Model event / observation | Actual implementation boundary |
| --- | --- |
| `init` | Instantiate [the shipped ResourceProvider](../../../package/src/pytest_obligation/integrations/django/owed_references.py). Its actual `_created` state initializes identity allocation. |
| `create` | Call `ResourceProvider.create()` without supplying an identity. Observe the returned name/object and actual subsequent listing. |
| `delete` | Call `ResourceProvider.delete()` for the emitted existing identity. |
| `reject-delete` | Call `delete(resource-0099)` and observe the actual `KeyError`, retained live resources and objects. |
| `inspect` | Read `ResourceProvider.list()` and compare each actual object with its retained first reference. Final model assertions emit this explicit read event rather than repeat the previous create/delete. |
| `observed` | Ordered live IDs, all IDs returned by actual creates, retained object identity and rejection status. Expectations are generated by Quint, not Python simulation. |

Histories include deletion of an earlier resource followed by recreation, deletion of the latest resource, repeated empty-provider recreation, and rejection interleaved with deletion/creation. Allocation must remain fresh across deletions, and an API call must not silently replace retained live objects.

## Repeatable mutation controls

Every normal run replays the same emitted traces against the fixed implementation and two declared mutants. Only a concrete `ReplayMismatch` counts as rejection.

- `length-allocation` compiles the actual current `create` method after changing only its counter increment to `len(self.resources) + 1`. Real construction and storage code remain in use. The emitted fresh-ID expectation exposes collisions/reuse after deletion.
- `copy-listed-objects` deliberately changes the listing output to equal deep copies. This explicit API-output mutant tests that replay checks retained object identity, not only names or collection lengths. It is not described as original source behavior.

Mutated methods are restored after every replay and never written into production source. Concrete expected/actual states and trace paths are recorded in the run artifact.

## Maintainer policy

Review changes to allocation, deletion, listing or resource identity together with the maintained model, adapter, manifest, witnesses and routing inputs in the **same change**. Preserve a discriminating old-source or implementation-mutant control. Do not suppress a mismatch by removing an observation/witness/mutant, weakening uniqueness or accepting setup exceptions. Any intended contract weakening needs explicit justification and maintainer review. Keep `audit.qnt` historical.

Topic documentation and `.qnt` files are executable-contract inputs: their changes must select the replay CI lane. Changes to implementation sources, adapter/manifest, shared runner or pinned toolchain must also select it. Shared mechanism changes run every registered topic.

## Bounds

At most four creations and nine API transitions are sampled, with arbitrary selected live deletions, monotonic identities, ordered listing and retained object checks. Django settings support class loading only; this is a shipped reference fake, not a database or upstream provider proof. Infinite histories, distributed services, concurrent calls and all Django versions are not certified. These are bounded replay contracts for drift prevention; unconnected broader audit models remain abstractions.
