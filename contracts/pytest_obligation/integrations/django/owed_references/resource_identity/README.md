# Stable identities in the shipped resource reference

[model.qnt](model.qnt) is a maintained bounded replay contract for the shipped `ResourceProvider`. [adapter.py](resource_identity_adapter.py) drives the **actual imported** `create`, `delete` and `list` methods with Quint-generated events and compares real observations with every emitted `observed` state. It records returned resource names and object references; it does not implement an alternative Python allocator or resource model.

[history/audit.qnt](history/audit.qnt) remains the unchanged historical pre-fix model from source revision `389c5bb84f7ab186fa9c7815c2e15cb9332b67a4`. Its length-derived allocation witness intentionally replaces a live identity. The immutable historical file's SHA-256 is recorded in [manifest.json](quint-connect.json); maintained behavior belongs in `model.qnt`.

## Run model checks and actual API replay

From the repository root, with Node.js 22+ and npm on `PATH`:

```sh
uv sync --locked --all-packages --no-default-groups --extra debt --extra django --extra celery --group xdist --group quint
uv run --no-sync pytest -c contracts/quint.ini contracts/pytest_obligation/integrations/django/owed_references/resource_identity
```

[pytest-quint-connect](https://github.com/gigaverse-app/pytest-quint-connect) installs its locked Quint **0.33.1**, checks the immutable `audit.qnt` hash, typechecks the maintained model, writes fresh ITF traces for every named witness and bounded sample, and replays each through [adapter.py](resource_identity_adapter.py) as its own pytest case ([guide](../../../../../README.md)). Missing witnesses or traces, unknown events, observation mismatches and surviving planted bugs fail; setup exceptions never count as detection.

The manifest fixes seed `20261107`, 150 sampled histories, 16 emitted sample traces of at most nine API transitions and four named witness traces. `.artifacts/quint-connect/` keeps ITF inputs, command logs, source hashes, the receipt and any `mismatch-*.json`; CI uploads them on failure too. Replay a saved trace with:

```sh
uv run --no-sync pytest -c contracts/quint.ini contracts/pytest_obligation/integrations/django/owed_references/resource_identity --quint-replay contracts/.artifacts/quint-connect/resource-identity/sample-0.itf.json
```

Minimal Django settings permit importing the real shipped module; **no database query, PostgreSQL server or production method patch is used in positive replay**.

## Source/action mapping

| Model event / observation | Actual implementation boundary |
| --- | --- |
| `init` | Instantiate [the shipped ResourceProvider](../../../../../../package/src/pytest_obligation/integrations/django/owed_references.py). Its actual `_created` state initializes identity allocation. |
| `create` | Call `ResourceProvider.create()` without supplying an identity. Observe the returned name/object and actual subsequent listing. |
| `delete` | Call `ResourceProvider.delete()` for an existing identity the model picks (`deleteResource`). |
| `rejectDelete` | Call `delete(resource-0099)` and observe the actual `KeyError`, retained live resources and objects. |
| `inspect` | Read `ResourceProvider.list()` and compare each actual object with its retained first reference. Final model assertions emit this explicit read event rather than repeat the previous create/delete. |
| `observed` | Ordered live IDs, all IDs returned by actual creates, retained object identity and rejection status. Expectations are generated by Quint, not Python simulation. |

Histories include deletion of an earlier resource followed by recreation, deletion of the latest resource, repeated empty-provider recreation, and rejection interleaved with deletion/creation. Allocation must remain fresh across deletions, and an API call must not silently replace retained live objects.

## Repeatable mutation controls

Every normal run replays the same emitted traces against the fixed implementation and two planted bugs. Only an observed-state mismatch counts as detection.

- `shipped-389c5bb` runs [`history/create-389c5bb.py.txt`](history/create-389c5bb.py.txt), the pre-fix `create` copied verbatim from `389c5bb` and pinned by SHA-256 in `resource_identity_adapter.py`. The manifest's `bugs_found` entry names it, so every history is replayed through it and the report shows how many diverge. It replaces the earlier `length-allocation` control, which compiled the same allocator into today's method.
- `copy-listed-objects` deliberately changes the listing output to equal deep copies. This explicit API-output mutant tests that replay checks retained object identity, not only names or collection lengths. It is not described as original source behavior.

Mutated methods are restored after every replay and never written into production source. Concrete expected/actual states and trace paths are recorded in the run artifact.

## Maintainer policy

Review changes to allocation, deletion, listing or resource identity together with the maintained model, adapter, manifest, witnesses and routing inputs in the **same change**. Preserve a discriminating old-source or implementation-mutant control. Do not suppress a mismatch by removing an observation/witness/mutant, weakening uniqueness or accepting setup exceptions. Any intended contract weakening needs explicit justification and maintainer review. Keep `audit.qnt` historical.

Topic documentation and `.qnt` files are executable-contract inputs: their changes must select the replay CI lane. Changes to implementation sources, adapter/manifest, shared runner or pinned toolchain must also select it. Shared mechanism changes run every registered topic.

## Bounds

At most four creations and nine API transitions are sampled, with arbitrary selected live deletions, monotonic identities, ordered listing and retained object checks. Django settings support class loading only; this is a shipped reference fake, not a database or upstream provider proof. Infinite histories, distributed services, concurrent calls and all Django versions are not certified. These are bounded replay contracts for drift prevention; unconnected broader audit models remain abstractions.
