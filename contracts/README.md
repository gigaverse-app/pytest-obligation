# Model contracts

A **contract** is a small [Quint](https://quint.sh) model of how one part of pytest-obligation must
behave, replayed against the real code by
[pytest-quint-connect](https://github.com/gigaverse-app/pytest-quint-connect). Quint generates
histories from the model; a driver applies each step to the real code and reads its state back;
any difference fails the test. Deliberately broken copies of the code ("planted bugs", or mutants)
must each make some history diverge, which proves the contract would notice that kind of bug.

They are test-time only: nothing here ships in the package, and the main test run never collects
this directory.

```sh
uv run --no-sync pytest -c contracts/quint.ini contracts
```

## Contracts

`contracts/` mirrors the import path of the code each contract models: the contract for
`pytest_obligation.references.in_memory` lives in `contracts/pytest_obligation/references/in_memory/`.

| Contract | Models | Real bug it found |
| --- | --- | --- |
| [resource-identity](pytest_obligation/integrations/django/owed_references/resource_identity/README.md) | `integrations/django/owed_references.py::ResourceProvider` | Deleting a resource let the next one overwrite a survivor (#211) |
| [fenced-lease](pytest_obligation/references/in_memory/fenced_lease/README.md) | Profile B's reference owner, `references/in_memory.py::InMemoryOwner` | A reaped owner's token stayed valid until the next claim (#217) |
| [report-merge](pytest_obligation/profiles/reporting/report_merge/README.md) | `profiles/reporting.py::merge_reports` | A rejected shard leaked evidence into the combined report (#210) |
| [cost-baseline](pytest_obligation/_cost_plugin/cost_baseline/README.md) | `_cost_plugin.py::CostCompleteness` | Update mode pruned the baseline after incomplete runs (#208) |

## One contract's files

[fenced-lease](pytest_obligation/references/in_memory/fenced_lease/) is the reference layout:

| File | Role |
| --- | --- |
| `README.md` | What is modelled and why, the rule, a diagram, the bug it found, limits |
| `model.qnt` | The model, opening with a header: what it models, covers, does not cover, when to update it |
| `quint-connect.json` | The manifest: each action mapped to the real call, bounds, planted bugs, `bugs_found` |
| `<name>_driver.py` | Generated by `pytest-quint-connect codegen quint-connect.json`. Never edit; regenerate |
| `conftest.py` | The driver: subclasses the generated base and calls the real code; defines the planted bugs |
| `test_<name>_contract.py` | One `quint_contract("quint-connect.json", driver=...)` line |
| `history/` | Frozen evidence, never edited: the shipped pre-fix code a planted bug runs, and any audit model that found a bug |

The other contracts still use hand-written `<name>_adapter.py` drivers, exposing
`create(root, work, mutant)`. They share one fixture, `adapter_driver`, in
[`conftest.py`](conftest.py), and declare `quint_contract("quint-connect.json", driver="adapter_driver")`.
Converting them to generated bases is follow-up work.

## Adding or changing a contract

1. Create `contracts/<import path of the modelled module>/<contract_name>/` with the files above.
2. Add a `Contract:` line to the modelled code's docstring pointing back at the directory.
3. Add the contract's name to `quint_required_contracts` in [`quint.ini`](quint.ini), and its
   modelled sources to the `quint` lane in `.github/test-lanes.json`.
4. Change the code, the model and the driver in the **same** pull request. Investigate a mismatch;
   never weaken the model, drop a witness or accept a surviving planted bug to make CI green.
5. When a contract finds a real bug: fix it with a regression test, record it in `bugs_found`, and
   keep a planted bug that runs the shipped pre-fix code from `history/`, so every report shows it
   is still caught.

For modelling advice (writing specs from code, witnesses, what a spec should state it does not
cover), see the skills in [quint-llm-kit](https://github.com/quint-co/quint-llm-kit/tree/main/quint-llm-kit-plugin/skills).

## Limits

These are bounded, serial, API-level checks of declared histories. They do not establish exhaustive
safety, liveness, arbitrary concurrency or behavior outside each model; the ordinary test suites
stay alongside them.
